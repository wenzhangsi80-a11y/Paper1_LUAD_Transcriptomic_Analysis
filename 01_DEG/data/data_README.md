# Data Inventory

This directory contains the input data and sample manifests used in the Paper 1 LUAD transcriptomic analyses.

## 1. Input Data

### GSE32863 expression assessment

The following original GEO files are required for the GSE32863 paired expression assessment.

| File | Source | Purpose | Required |
|:----------------------------|:-------------|:-------------|:-------------|
| `data/input_data/GSE32863_series_matrix.txt.gz` | GEO: GSE32863 | Expression matrix and sample-level metadata | Yes |
| `data/input_data/GPL6884-11607.txt` | GEO: GPL6884 | Probe-to-gene annotation | Yes |

Both files are used by:

`scripts/01_DEG/GitHub1_Paper1_differential_expression_GSE32863.R`

The Series Matrix file is also used by:

`scripts/01_DEG/GitHub1A_GSE32863_Sample_Manifest_Export.R`

Download the original files from:

- GSE32863: <https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE32863>
- GPL6884: <https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GPL6884>

Place the downloaded files in `data/input_data/` without changing their filenames.

## 2. Generated Sample Manifests

The sample-manifest export script:

`scripts/01_DEG/GitHub1A_GSE32863_Sample_Manifest_Export.R`

generates the following files in `data/sample_manifests/GSE32863/`.

| File | Description |
|:--------------------------------------------|:-------------------------|
| `GSE32863_complete_sample_manifest.csv` | Complete metadata for all 116 samples, including GEO accession, subject identifier, standardized tissue group, original tissue annotation, sample type, title, and source |
| `GSE32863_57_complete_pairs.csv` | The 57 subjects with exactly one tumor sample and one adjacent-normal sample |
| `GSE32863_singleton_samples_excluded_from_paired_analysis.csv` | The two singleton samples that lack a matched tissue sample and are therefore excluded from paired statistical testing |

### Audited cohort composition

| Cohort characteristic               | Number |
|:------------------------------------|-------:|
| Total samples                       |    116 |
| Tumor samples                       |     58 |
| Adjacent-normal samples             |     58 |
| Unique subjects                     |     59 |
| Complete tumor--normal pairs        |     57 |
| Samples included in paired analysis |    114 |
| Singleton subjects                  |      2 |
| Tumor-only samples                  |      1 |
| Normal-only samples                 |      1 |

The complete sample manifest retains all 116 samples. Only the 57 complete pairs (114 samples) are used for paired expression comparisons.

The two singleton samples are:

| Subject | GEO accession | Group  | Reason for exclusion              |
|:--------|:--------------|:-------|:----------------------------------|
| 3023    | GSM813507     | Tumor  | No matched adjacent-normal sample |
| 3035    | GSM813518     | Normal | No matched tumor sample           |

These samples are excluded from paired testing only; they remain documented in the complete cohort manifest.

## 3. Data Handling and Sample Matching

- GEO accession identifiers are used to align sample metadata with expression matrix columns.
- Subject identifiers are used to identify matched tumor--normal samples.
- The original `tissue:ch1` metadata field is used to distinguish Lung tumor from Normal lung.
- The standardized `Group` field records the corresponding Tumor or Normal classification.
- GPL6884 probe identifiers are used for probe-to-gene mapping in the expression-analysis script.
- For each target gene, the probe with the highest mean expression across all 116 samples is selected.
- Paired expression comparisons use only the 57 complete tumor--normal pairs.

## 4. Reproducibility

The sample manifests are generated by the dedicated sample-manifest export script rather than being assumed to be historical outputs of the original expression-analysis workflow.

The script performs cohort-count checks and verifies the consistency of sample identifiers across the complete manifest, paired manifest, and singleton manifest.

The generated CSV files can be recreated by running the following command from the project root:

``` r
source("scripts/01_DEG/GitHub1A_GSE32863_Sample_Manifest_Export.R")
```

The original GEO input files should be retained unchanged to support reproducibility and sample-level traceability.
