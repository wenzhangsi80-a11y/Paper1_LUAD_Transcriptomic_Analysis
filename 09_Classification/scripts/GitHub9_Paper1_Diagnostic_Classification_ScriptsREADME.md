# Diagnostic Classification Scripts

## Overview

This directory contains the R scripts used to implement the diagnostic-classification-related workflow for the LUAD study:

**Integrated transcriptomic and single-cell characterization of AOC3, MS4A7, and IL7R across the TME in LUAD**

The principal script is:

`GitHub9_Paper1_Diagnostic_Classification.R`

The workflow uses three prioritized study genes:

- `AOC3`
- `MS4A7`
- `IL7R`

The classification analysis examines exploratory transcriptomic discrimination between LUAD tumor and normal tissue samples. It integrates historical data provenance audits, sample and subject identification, expression-scale compatibility checks, model-definition locking, internal performance assessment, final model fitting, external dataset assessment, paired expression analysis, and figure generation.

The workflow is organized into sequential components under WORKFLOW-13. Each component is designed to maintain traceability between the historical analysis inputs, locked model specification, statistical outputs, and manuscript-facing results.

The historical Xiangtao-derived TCGA ROC branch and the revised Sangerbox-derived tumor-only WGCNA branch are treated as distinct analytical data branches. Their sample counts and analytical purposes are not interchangeable.

### 3.3. `STEP13C-4` — GEO Metadata and Subject-ID Mapping Audit

**Objective**

Investigate whether the archived GEO metadata supports a reliable mapping between GSE32863 sample accessions, sample codes, and subject identifiers.

The workflow is divided into the following components:

| Component | Purpose |
|---|---|
| `STEP13C-4A` | Historical object and metadata inventory |
| `STEP13C-4B` | Historical sample-ID source and uniqueness audit |
| `STEP13C-4C` | Local GEO metadata source inspection |
| `STEP13C-4D` | GSM-to-sample-code mapping audit |
| `STEP13C-4E` | Final matched sample-code structure audit |
| `STEP13C-4F` | Complete GEO subject-ID concordance audit |

**STEP13C-4D: Sample-code mapping**

The workflow extracts GSM accessions, sample titles, and source fields from the Series Matrix and searches the metadata for patient-, subject-, pair-, and matching-related information.

It then:

- Parses sample codes from sample titles.
- Derives Normal/Tumor labels from `_N` and `_T` title suffixes.
- Evaluates sample-code multiplicity.
- Identifies candidate codes with exactly two records.
- Checks whether candidate pairs contain one Normal and one Tumor record.
- Investigates non-complete sample-code groups and singleton records.
- Compares title-derived labels with historical group information when available.

The extracted sample codes are initially treated as candidate identifiers, not automatically as validated patient identifiers.

**STEP13C-4E: Matched-pair structure audit**

Using the `mapping_df` object generated by STEP13C-4D, this component:

- Constructs complete Normal–Tumor pairs from sample codes.
- Assigns sequential Pair_ID values.
- Identifies unmatched or nonstandard sample-code groups.
- Audits Normal and Tumor record reconstruction.
- Checks GSM uniqueness and completeness.
- Searches GEO metadata for additional semantic evidence.
- Records a conservative interpretation of the sample-code pairing structure.

**STEP13C-4F: Subject-ID concordance**

This component compares explicit subject identifiers from the Family SOFT metadata with sample codes extracted from Series Matrix titles.

It:

- Parses the 116 GSM records from both metadata sources.
- Extracts explicit `subject:` and `sample id:` characteristics.
- Checks GSM set concordance.
- Compares subject identifiers with title-derived sample codes using exact string matching.
- Audits multiple-code subject assignments.
- Classifies subject-level structures.
- Evaluates the expected numbers of complete pairs and singleton subjects.

The expected structure is:

- 116 samples.
- 58 Normal samples.
- 58 Tumor samples.
- 59 unique subjects.
- 57 complete Normal–Tumor pairs.
- One Tumor-only subject (3023).
- One Normal-only subject (3035).
- No other subject structures.

### 3.4. `STEP13C-5` — Final GSE32863 Input and Subject-Pairing Lock

**Objective**

**Main procedures**

## 5. Model Definition Lock

### `STEP13F` — Prespecified Model Definition and Analysis-Policy Lock

**Objective**

Define and audit the prespecified three-gene classification model and establish restrictions for all downstream analyses.

**Locked predictors**

- `AOC3`
- `MS4A7`
- `IL7R`

**Outcome definition**

- Binary outcome: `TumorStatus`
- Reference class: Normal
- Positive class: Tumor

**Prespecified model**

`TumorStatus ~ AOC3 + MS4A7 + IL7R`

The specified model is a multivariable logistic regression fitted using a binomial family and logit link.

**Validation policy**

The model-definition lock records the intended cross-validation settings:

- 10 outer folds.
- 10 inner folds.
- Stratified fold assignment.
- No data-driven feature selection.

The actual implementation of the inner folds is documented separately in STEP13G.

**External-analysis restrictions**

The model-definition lock explicitly prohibits:

- External model refitting.
- External coefficient estimation.
- External feature selection.
- External threshold optimization.
- External cutpoint searching.
- External model tuning.

**Main procedures**

- Define model-lock variables.
- Verify the required model-definition objects.
- Evaluate 33 predefined integrity checks.
- Construct and export the integrity-check table.
- Determine the overall PASS/FAIL status.
- Save the model-definition lock as an RDS object.
- Export human-readable model-definition and operation-policy reports.
- Record allowed and prohibited downstream operations.
- Save session information and a conditional status marker.

STEP13F is a model-definition and documentation step. It does not fit the classification model or calculate model-performance metrics.

## 6. Internal TCGA Cross-Validation Performance Assessment

### `STEP13G` — Internal Cross-Validation

**Objective**

Evaluate the exploratory tumor-versus-normal classification performance of the prespecified three-gene logistic regression model using the historical TCGA classification dataset.

**Input**

Historical TCGA ROC data workspace:

`Paper1_Figure2_Figure12_TCGA_LUAD_ROC_etal/.RData`

Required data object:

`df_wide`

Expected input structure:

- 575 samples.
- 516 Tumor samples.
- 59 Normal samples.

Required columns:

- `sample_id`
- `status`
- `AOC3`
- `MS4A7`
- `IL7R`

**Model**

`TumorStatus ~ AOC3 + MS4A7 + IL7R`

The model is fitted using `glm()` with a binomial family.

**Outer-fold procedure**

1. Generate 10 stratified outer folds.
2. Hold out each outer test set.
3. Use the remaining samples as the outer training set.
4. Fit the prespecified logistic regression model in each outer training set.
5. Predict probabilities for the corresponding held-out samples.
6. Retain fold assignments and model coefficients for auditing.
7. Combine held-out predictions into an out-of-fold prediction table.

**Inner-fold audit**

Within each outer training set, the workflow generates 10 inner-fold assignments and records the corresponding sample counts and class distributions.

The current implementation does not use the inner folds for:

- Inner-loop model fitting.
- Inner-level validation.
- Feature selection.
- Model selection.
- Threshold selection.
- Hyperparameter tuning.

Therefore, despite the historical workflow and directory naming conventions, the implemented procedure should not be described as a fully executed conventional nested cross-validation procedure. The primary performance assessment is based on stratified 10-fold outer cross-validation and its out-of-fold predictions.

**Performance assessment**

The workflow calculates:

- OOF ROC curve and AUC.
- AUC 95% confidence interval.
- Sensitivity.
- Specificity.
- Accuracy.
- Balanced accuracy.
- Positive predictive value.
- Negative predictive value.
- Brier score.

Classification metrics use the prespecified probability threshold of 0.50. No data-derived threshold optimization is performed.

**Reproducibility**

- Random seed: `20260926`.
- Project-relative paths: `here::here()`.
- Model formula, study genes, expected sample counts, and classification threshold are prespecified.

**Outputs**

The workflow exports input and model-definition audits, sample-count and complete-case audits, outer-fold and inner-fold stratification records, OOF predictions, fold-specific coefficients, performance summaries, confusion matrices, final audit checks, serialized results, human-readable reports, session information, and conditional PASS/FAIL status markers.

## 7. Final TCGA Logistic Regression Model

### `STEP13H` — TCGA Final Model

**Objective**

Fit the final prespecified multivariable logistic regression model using all eligible observations in the historical 575-sample TCGA classification branch.

**Inputs**

- `STEP13F_Model_Definition_Lock_FINAL.rds`
- `STEP13G_Nested_CV_FINAL.rds`
- Historical TCGA RData workspace

**Sample composition**

- Total: 575.
- Tumor: 516.
- Normal: 59.

**Model specification**

`TumorStatus ~ AOC3 + MS4A7 + IL7R`

- Outcome reference: Normal.
- Positive class: Tumor.
- Model: Multivariable logistic regression.
- Family: Binomial.
- Link: Logit.

**Main procedures**

1. Verify the STEP13F model-definition lock.
2. Audit required historical TCGA objects.
3. Verify expected sample counts and outcome levels.
4. Audit sample identifiers and complete-case retention.
5. Check predictor values for missing and non-finite values.
6. Fit the final logistic regression model using the locked observations.
7. Audit model convergence, coefficient finiteness, and model rank.
8. Extract coefficients, standard errors, z statistics, and P values.
9. Calculate odds ratios and 95% Wald confidence intervals.
10. Save model predictions for traceability.
11. Verify the preceding STEP13G checkpoint.
12. Aggregate final audit checks and write the final status marker.

**Model restrictions**

STEP13H does not perform feature selection, gene selection, model tuning, external refitting, external coefficient estimation, or external threshold optimization.

The final fitted model and its coefficients are retained for STEP13I external assessment.

**Reproducibility**

- Random seed: `20260926`.
- Required analysis package checked by the script: `pROC`.
- Path-resolution package: `here`.

STEP13H is a final model-fitting step using the historical TCGA dataset. It is not a cross-validation procedure and does not use STEP13G fold-specific coefficients to fit the final model.

## 8. GSE32863 External Assessment and Paired Expression Analysis

### `STEP13I` — Locked-Model External Assessment

**Objective**

Apply the locked STEP13H TCGA logistic regression model to the historical GSE32863 dataset without refitting the model or estimating new coefficients from the external data.

**Locked model**

`TumorStatus ~ AOC3 + MS4A7 + IL7R`

**Main procedures**

1. Read and verify the STEP13F model-definition lock.
2. Audit external-analysis prohibition settings.
3. Load and validate the STEP13H final model.
4. Verify the logistic-regression model structure.
5. Extract and audit the locked model coefficients.
6. Load the historical GSE32863 expression objects.
7. Audit sample counts and expression-object structures.
8. Verify sample-ID sets and group-label concordance.
9. Confirm the availability of AOC3, MS4A7, and IL7R.
10. Extract the external expression matrix.
11. Audit expression-value integrity and model-input completeness.
12. Apply the locked STEP13H model using `predict()`.
13. Calculate external ROC/AUC and the corresponding 95% confidence interval.
14. Record prohibited external-analysis operations.
15. Verify that the TCGA model coefficients remain unchanged.

**External-analysis restrictions**

The workflow does not perform:

- External model refitting.
- External coefficient estimation.
- External feature selection.
- External threshold optimization.
- External cutpoint searching.
- External model tuning.

The analysis is a locked-model external assessment, not external model development.

### 8.1. GSE32863 Subject-Level Paired Expression Analysis

The STEP13I workflow also performs a separate paired expression analysis using the 57 complete Normal–Tumor subject pairs identified through the GEO metadata audits.

**Main procedures**

- Use the metadata-supported subject mapping.
- Construct the 57 complete Normal–Tumor pairs.
- Extract paired expression values for AOC3, MS4A7, and IL7R.
- Calculate Normal and Tumor expression medians.
- Calculate paired expression differences.
- Perform two-sided paired Wilcoxon signed-rank tests.
- Apply Benjamini–Hochberg correction across the three genes.
- Export gene-level paired-expression traceability records.
- Audit the paired sample structure and statistical result records.

The paired expression analysis is separate from the external ROC assessment and does not alter the locked model coefficients.

**Important interpretation note**

External ROC/AUC performance and classification at a fixed probability threshold represent different aspects of model performance. A high external AUC indicates strong rank-based discrimination in the evaluated dataset but does not by itself establish probability calibration or successful transfer of the original classification threshold.

The external expression-scale compatibility and fixed-threshold results should therefore be interpreted separately.

## 14. Analytical Scope and Interpretation Restrictions

The classification workflow is designed to assess exploratory transcriptomic discrimination using three prioritized study genes. Its results should be interpreted within the limits of the underlying historical datasets and the implemented analysis procedures.

The following restrictions apply throughout the workflow:

1. **No unsupported clinical diagnostic claims.** The analyses do not establish clinical diagnostic utility or clinical biomarker validity.

2. **No causal interpretation.** The classification results do not demonstrate that AOC3, MS4A7, or IL7R causes tumor development or drives a specific biological mechanism.

3. **Historical and revised TCGA branches remain distinct.** The historical 575-sample classification branch must not be conflated with the current 574-record annotation or the 572-sample eligible primary-tumor-versus-normal cohort.

4. **The historical 516-tumor count is not independently established as a verified expression-sample count.** It is retained as a historical branch definition rather than used to redefine the revised TCGA cohort.

5. **The GSE32863 sample structure is metadata-supported.** The 57 complete subject-level pairs are based on GEO metadata concordance. The two singleton subjects are not artificially paired.

6. **The inner-fold procedure is not a fully executed nested cross-validation analysis.** STEP13G records inner-fold stratification information but does not perform inner-loop model fitting or model selection.

7. **The final TCGA model is distinct from the cross-validation models.** STEP13H fits a final model using the historical TCGA classification input; it does not use STEP13G fold-specific coefficients as the final model.

8. **External model parameters remain locked.** STEP13I applies the STEP13H model to GSE32863 without external refitting, coefficient estimation, feature selection, or threshold optimization.

9. **External AUC and fixed-threshold classification are distinct.** Strong rank-based discrimination does not necessarily indicate successful transfer of the original probability threshold or adequate probability calibration.

10. **Paired expression testing is separate from ROC assessment.** The paired Wilcoxon tests and FDR adjustment do not alter the classification model or its coefficients.

11. **Figure generation uses locked upstream results.** The visualization steps do not independently refit models, recalculate cross-validation, or repeat paired-expression hypothesis testing.

12. **Audit status is not equivalent to independent validation.** PASS/FAIL markers indicate whether predefined structural or traceability conditions were satisfied; they do not establish clinical validity or independent diagnostic performance.
